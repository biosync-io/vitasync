Progressive Web App (PWA)

import { Aside, Steps, Tabs, TabItem } from ‘@astrojs/starlight/components’;

The VitaSync web dashboard is a full-featured Progressive Web App — installable on desktop and mobile, offline-capable with intelligent caching, and push-notification enabled.

Setup

Section titled “Setup”

The PWA works out of the box with no extra configuration needed. The service worker is automatically generated during next build by @ducanh2912/next-pwa.

Push Notifications (Optional)

Section titled “Push Notifications (Optional)”

To enable push notifications, generate VAPID keys and add them to your environment:

  1. Generate VAPID keys

    This outputs a public/private key pair.

  2. Add to environment

  3. Restart the web service

    Users will be prompted to allow notifications when they visit the dashboard.
VAPID keys only need to be generated once. The same key pair should be used across all environments and deployments. Changing keys will invalidate all existing push subscriptions.

Caching Strategy

Section titled “Caching Strategy”

The service worker uses different strategies depending on the resource type:

ResourceStrategyCache NameTTL
Next.js build outputPrecacheworkbox-precacheUntil next build
Icons (/icons/*.png)CacheFirsticon-cache30 days
Google Fonts CSSStaleWhileRevalidategoogle-fonts-stylesheets—
Google Fonts filesCacheFirstgoogle-fonts-webfonts1 year
API data (/api/v1/*)NetworkFirstapi-cache5 min, 10s timeout

API data uses **NetworkFirst** with a 10-second timeout. If the network is slow or unavailable, the cached response is returned immediately. This means dashboard charts and metrics can display stale data while offline — better than showing nothing.

Offline Mutations

Section titled “Offline Mutations”

When the device is offline, write operations (POST/PUT/DELETE to /api/v1/*) are queued in IndexedDB under the vitasync-offline database. When connectivity returns, the service worker replays them in order via the Background Sync API.

Supported offline actions include:

  • Logging water intake
  • Recording mood entries
  • Writing journal entries
  • Updating habit check-ins
Background Sync is only supported in Chromium browsers (Chrome, Edge). On Safari and Firefox, offline mutations are stored but won't auto-replay — the user needs to retry manually when back online.

Custom Service Worker

Section titled “Custom Service Worker”

The custom service worker code lives in apps/web/service-worker/index.ts. It is merged with the Workbox-generated service worker by next-pwa at build time. It handles:

  • Push events — parses notification payload and shows a system notification
  • Notification clicks — opens or focuses the relevant dashboard page
  • Background sync — replays queued offline mutations from IndexedDB
  • Periodic sync — refreshes health scores, readiness, and insights

Troubleshooting

Section titled “Troubleshooting”

Service worker not registering

Section titled “Service worker not registering”
  • Service workers only work over HTTPS or on localhost
  • In development, the service worker is disabled by default (set disable: false in next.config.mjs to test)
  • Check DevTools → Application → Service Workers for registration status

Push notifications not working

Section titled “Push notifications not working”
  • Verify VAPID keys are set in environment variables
  • Check that the user granted notification permission (DevTools → Application → Notifications)
  • On iOS, push notifications require Safari 16.4+ and the app must be added to Home Screen

Offline page showing unexpectedly

Section titled “Offline page showing unexpectedly”
  • Clear the service worker cache: DevTools → Application → Storage → Clear site data
  • Rebuild the app to regenerate the service worker: pnpm --filter @biosync-io/web build

Icons not displaying

Section titled “Icons not displaying”
  • Regenerate icons: pnpm --filter @biosync-io/web generate-icons
  • Verify files exist in apps/web/public/icons/
